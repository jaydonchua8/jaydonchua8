## About

Computer Science undergraduate at the University of Illinois Urbana-Champaign, building software across **low-latency systems**, **full stack product engineering**, and **applied AI tooling**.

My systems work centers on market data infrastructure — a Java limit order book that decodes CME's own feed and reconstructs depth-of-book state, built to be correct under packet loss rather than merely fast in the happy case. My product work runs the other direction: TypeScript and React applications taken from schema design through API contracts to a shipped interface, including a public, MIT-licensed developer tool with a tested CI matrix.

I approach AI as an engineering surface, not a research project — local-first vision and OCR pipelines, structured model outputs, and evaluation that can be regression-tested like any other system.

I build with a **product engineering mindset**: scope against real users, cut to a shippable core, instrument what matters, and let feedback — not speculation — drive the next iteration. Currently building a venture-backed-track social product through Y Combinator Startup School with a cofounder.

## Featured Projects

<details>
<summary><b>snapcal — Screenshot to Calendar Event CLI</b></summary>

<br/>

A macOS command-line tool that turns a screenshot of a schedule, poster, or listing into a calendar event. Point it at an image, get back a valid `.ics` file — no accounts, no API keys, no network round trip.

| Attribute | Detail |
| :--- | :--- |
| **Stack** | Python, Swift OCR helper, Apple Vision framework, pytest, GitHub Actions |
| **Scale** | Handles arbitrary unstructured event imagery — posters, messages, screenshots, syllabi |
| **Performance** | Fully local OCR and parsing; single-command execution with no network dependency or cold-start latency |
| **Security** | No API keys, no OAuth flow, no stored tokens, no image upload — every byte stays on the machine |
| **Impact** | Public, MIT licensed, CI-verified across Python 3.9–3.13 |
| **Repository** | [github.com/jaydonchua8/snapcal →](https://github.com/jaydonchua8/snapcal) |

The architectural decision that defines this project is emitting a standard `.ics` file instead of writing directly to Google Calendar. Direct integration would have required OAuth, an app registration, and persistent tokens — real security surface for a tool that runs in under a second. The `.ics` boundary keeps the tool calendar-agnostic and dependency-free, and it works with any client the user already has. Driven end to end by a macOS Shortcuts hotkey that captures the screen and pipes the image straight into the CLI.

</details>

<details>
<summary><b>CME Limit Order Book — Market Data Reconstruction Engine</b></summary>

<br/>

A Java limit order book that decodes CME's market data feed and reconstructs full depth-of-book state from the raw exchange protocol — written against the real feed format rather than a simplified teaching model.

| Attribute | Detail |
| :--- | :--- |
| **Stack** | Java, CME market data feed decoding, custom order book data structures, JUnit |
| **Scale** | Full depth-of-book reconstruction from live-format exchange message streams |
| **Performance** | Allocation-conscious hot path, constant-time best bid/ask access, price-level structures sized for sustained message pressure |
| **Security** | Bounds-checked binary decoding, strict frame validation, defensive handling of malformed and out-of-sequence messages |
| **Impact** | Working reference implementation for exchange protocol decoding and book state machines |
| **Repository** | [github.com/jaydonchua8/cme-orderbook →](https://github.com/jaydonchua8/cme-orderbook) |

Transport decoding is deliberately separated from book state so the matching and depth logic can be tested deterministically against recorded message sequences. Sequence-gap detection and recovery are modeled as first-class states rather than error handling, because a book that silently diverges after one dropped packet is worse than one that is slow.

</details>

<details>
<summary><b>LeetStrat — Strategy-First Interview Trainer</b></summary>

<br/>

A web application that trains the step most candidates actually fail: choosing the approach. Before writing a line of code, users commit to a data structure, an algorithmic technique, a time and space complexity, and the edge cases — then get evaluated on that reasoning.

| Attribute | Detail |
| :--- | :--- |
| **Stack** | TypeScript, Node.js, Express, Prisma ORM, PostgreSQL |
| **Scale** | Problem catalog spanning core algorithmic patterns with per-user attempt history |
| **Performance** | Prisma-backed query layer over a normalized schema, cached problem metadata, stateless API surface |
| **Security** | Session-scoped access control, validated request payloads, per-user data isolation at the query layer |
| **Impact** | Built for and used by a cohort of peers preparing for Summer 2027 SWE internships |
| **Repository** | [github.com/jaydonchua8/leetstrat →](https://github.com/jaydonchua8/leetstrat) |

The product thesis is that grinding solutions builds recall while grinding *strategy* builds transfer. Scoping decisions followed from that: a gamified practice mode and a full code-execution environment were both cut to keep the training loop — problem in, approach out, feedback returned — as the entire surface area of the product.

</details>

<details>
<summary><b>Tether — Proximity-Based Social Platform</b></summary>

<br/>

A mobile application for meeting people nearby: a live map, tailored events, mutual interests and connections, and a credibility system that makes strangers legible. Built with a cofounder through Y Combinator Startup School, launching first at UIUC.

| Attribute | Detail |
| :--- | :--- |
| **Stack** | React Native, Expo, TypeScript, Supabase, PostgreSQL with PostGIS, EAS build pipeline |
| **Scale** | Geospatial matching across a campus-scale user base, designed for store-ready release |
| **Performance** | PostGIS-indexed proximity queries, incremental Supabase migrations, over-the-air update delivery via EAS |
| **Security** | Location sharing **off by default** — enabled only by an explicit one-hour session; credibility anchored on verified `.edu` identity plus post-meetup peer review |
| **Impact** | Y Combinator Startup School project; $25K in startup credits secured |
| **Repository** | `Private — available on request` |

The defining constraint is anti-stalking. Every always-on location product creates a surveillance vector, so proximity here is a deliberate, time-boxed action rather than a background state. Matching surfaces a *percentage* of shared interests instead of exposing raw interest tags — enough signal to justify meeting someone, not enough to profile them.

</details>

<details>
<summary><b>WTM — Travel Activity Discovery & Recap</b></summary>

<br/>

A cross-platform app for people who land somewhere new and don't know what to do — and for showing off the niche things they've actually done. Logs are free text in the user's own words, not categories picked off a list.

| Attribute | Detail |
| :--- | :--- |
| **Stack** | React Native, Expo, TypeScript, runs on web and mobile |
| **Scale** | Location-scoped discovery with per-user activity history and a social follower graph |
| **Performance** | Shared Expo codebase across web and native targets, paginated feeds, client-side caching of repeat lookups |
| **Security** | Authenticated mutations, user-scoped activity data, opt-in tagging of other users after a log |
| **Impact** | Hackathon build reframed into a travel product with a Wrapped-style automatic recap |
| **Repository** | `Private — available on request` |

Treating a logged activity as an immutable free-text event rather than a categorized row is what makes the rest of the product possible: the feed, the follower graph, the recap, and niche-activity discovery all fall out of one abstraction. Recommendations blend with a user's existing taste rather than overriding it, and the trip recap triggers automatically on returning home.

</details>
